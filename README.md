# آبرنگ (Abrang) — فروشگاه آنلاین لوازم‌التحریر

سایت فروشگاهی «آبرنگ» با وردپرس + ووکامرس، کاملاً فارسی و راست‌چین (RTL)، با قیمت‌ها به تومان.
همه‌چیز برای ساخت دوبارهٔ سایت داخل همین مخزن (repo) است: محیط Docker، اسکریپت نصب خودکار (`setup.sh`) و قالب اختصاصی آبرنگ.
دیتابیس، فایل‌های آپلودشده و رمزها **هرگز** داخل گیت ذخیره نمی‌شوند. توضیح چرایی این معماری: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

> **وضعیت فعلی (قدم ۳ از ۵):** فروشگاه، آرشیو دسته‌ها، صفحهٔ تکی محصول (با محصول متغیر ۴ رنگ)، جستجو و ۴۰۴ فارسی آماده‌اند؛ ورود دسته‌جمعی با اکسل/CSV و پوشهٔ تصاویر بر اساس SKU فعال است.
> پرداخت، ارسال، متن حقوقی، سئو و انتشار در مراحل بعدی هستند.
> گزارش پیشرفت قدم‌به‌قدم: [PROGRESS.md](PROGRESS.md)

## راه‌اندازی قدم‌به‌قدم (PowerShell)

### قدم ۰ — Docker Desktop را روشن کنید
از منوی Start برنامه **Docker Desktop** را باز کنید و حدود یک دقیقه صبر کنید تا پایین پنجره‌اش بنویسد **Engine running** (آیکون نهنگ در کنار ساعت ویندوز ثابت می‌شود).
✅ نتیجه: Docker آماده است. تا این مرحله انجام نشده، هیچ‌کدام از دستورهای بعدی کار نمی‌کنند.

### قدم ۱ — پروژه را روی کامپیوترتان بگیرید
```powershell
git clone https://github.com/Mmziii/Abrang.git
```
سپس وارد پوشه شوید:
```powershell
cd Abrang
```
✅ نتیجه: پوشه‌ای به نام `Abrang` ساخته می‌شود و خط فرمان داخل آن قرار می‌گیرد. **همه دستورهای بعدی را داخل همین پوشه بزنید.**

### قدم ۲ — فایل تنظیمات محلی را بسازید
```powershell
Copy-Item .env.example .env
```
✅ نتیجه: هیچ پیامی چاپ نمی‌شود — یعنی درست انجام شده. (فایل `.env` رمزهای نسخهٔ محلی شماست و هیچ‌وقت به گیت نمی‌رود.)

### قدم ۳ — سایت را روشن کنید (دیتابیس + وردپرس)
```powershell
docker compose up -d
```
✅ نتیجه: بار اول چند دقیقه دانلود طول می‌کشد؛ در پایان خط‌هایی مثل `Container abrang-wordpress Started` می‌بینید. بعد از آن حدود یک دقیقه صبر کنید تا وردپرس کامل بالا بیاید.

> 💡 در Docker Desktop ممکن است کانتینری به نام `wpcli` نبینید یا خاموش باشد؛ طبیعی است، آن ابزار فقط موقع قدم ۴ برای چند لحظه روشن و خاموش می‌شود.

### قدم ۴ — نصب و تنظیم خودکار سایت (فارسی‌سازی، ووکامرس، قالب)
```powershell
docker compose run --rm wpcli bash /scripts/setup.sh
```
✅ نتیجه: قدم‌ها یکی‌یکی با علامت `==>` چاپ می‌شوند (بار اول چند دقیقه طول می‌کشد چون ووکامرس دانلود می‌شود) و در آخر این خط را می‌بینید:

```
==> Done ✔  Abrang is ready.
```

این دستور را هر چند بار بزنید امن است؛ از بار دوم به بعد برای هر قدم می‌نویسد `[already done]` یعنی «قابلی انجام شده، دست نمی‌زنم».

### قدم ۵ — سایت را باز کنید
| کجا | آدرس |
|---|---|
| خودِ سایت | http://localhost:8080 |
| فروشگاه | http://localhost:8080/shop/ |
| پیشخوان مدیریت وردپرس | http://localhost:8080/wp-admin |

ورود به پیشخوان (همانی که در فایل `.env` هست — فقط برای کامپیوتر خودتان):

- نام کاربری: `admin`
- رمز عبور: `abrang-admin-1234`

✅ نتیجه: سایتی فارسی و راست‌چین با اسم «آبرنگ» می‌بینید. صفحهٔ نخست فروشگاه و محصولات نمونه (در صورت فعال بودن پرچم نمونه) نمایش داده می‌شود.

## کارهای روزمره

**خاموش کردن سایت** (اطلاعات پاک نمی‌شود):
```powershell
docker compose down
```

**روشن کردن دوباره:**
```powershell
docker compose up -d
```

**دیدن وضعیت** (هر دو کانتینر `db` و `wordpress` باید `Up` یا `healthy` باشند):
```powershell
docker compose ps
```

**گرفتن آخرین نسخه کد از گیت‌هاب و اعمال آن:**
```powershell
git pull
```
```powershell
docker compose run --rm wpcli bash /scripts/setup.sh
```

**شروع کاملاً از صفر** — ⚠️ این کار دیتابیس و عکس‌های آپلودشدهٔ نسخهٔ محلی را پاک می‌کند (روی کامپیوترتان فقط، نه روی گیت):
```powershell
docker compose down -v
```
```powershell
docker compose up -d
```
```powershell
docker compose run --rm wpcli bash /scripts/setup.sh
```
✅ نتیجه: سایتی تازه دقیقاً مثل روز اول ساخته می‌شود.

## اگر مشکلی پیش آمد

**خطای شبیه `error during connect` یا `docker daemon is not running`**
→ Docker Desktop روشن نیست یا هنوز کامل بالا نیامده. آن را باز کنید، صبر کنید `Engine running` شود، بعد دستور را دوباره بزنید.

**خطای شبیه `port is already allocated` یا `address already in use` موقع `docker compose up -d`**
→ پورت 8080 را برنامهٔ دیگری گرفته (مثلاً یک وردپرس دیگر یا XAMPP). یا آن برنامه را ببندید، یا پورت آبرنگ را عوض کنید:
فایل `.env` را با Notepad باز کنید و در **دو** خط، `8080` را به `8081` تغییر دهید (`WP_URL` و `WP_PORT`)، ذخیره کنید، و بعد:
```powershell
docker compose down
```
```powershell
docker compose up -d
```
```powershell
docker compose run --rm wpcli bash /scripts/setup.sh
```
از این به بعد سایت را با http://localhost:8081 باز کنید.

**خطای عجیب شامل `$'\r'` یا `command not found` داخل قدم ۴**
→ انتهای خط‌های اسکریپت خراب شده (CRLF ویندوزی). مخزن خودش با فایل `.gitattributes` جلوی این را می‌گیرد؛ پس معمولاً یعنی فایل `scripts/setup.sh` با یک ویرایشگر دستی تغییر کرده.
فایل‌های `.sh` را با Notepad/Word باز و ذخیره نکنید. برای برگرداندن نسخه سالم:
```powershell
git checkout -- scripts/setup.sh
```

**سایت در مرورگر باز نمی‌شود**
→ اول `docker compose ps` را بزنید؛ اگر چیزی `Exit` شده بود:
```powershell
docker compose down
```
```powershell
docker compose up -d
```
یک دقیقه صبر کنید و دوباره http://localhost:8080 را باز کنید.

**رمز پیشخوان را فراموش کردید**
→ رمز فعلی در فایل `.env` (خط `WP_ADMIN_PASSWORD`) همان است که موقع اولین نصب ساخته شده.
اگر داخل پیشخوان رمزی را عوض کرده‌اید و یادتان رفته، با «شروع از صفر» در بالا سایت تازه با همان رمز `.env` ساخته می‌شود (فقط روی کامپیوترتان).

## طراحی فروشگاه و محصولات نمونه (قدم ۲)

صفحهٔ نخست اکنون شامل جستجو، منوی دسته‌ها، محصولات و پابرگ است. تمام اطلاعات تماس،
وعدهٔ ارسال رایگان، شبکه‌های اجتماعی و متن‌های معرفی **نمونه و نیازمند تأیید مالک** هستند.
برگه‌های قوانین و حریم خصوصی هنوز متن حقوقی واقعی ندارند.

`ABRANG_DEMO=1` در تنظیمات نمونه فقط برای طراحی محلی است: ۱۲ محصول ساختگی با
برچسب «نمونه آزمایشی» و تصاویر هندسی تولیدشده می‌سازد. روی سایت واقعی این مقدار باید
`0` یا حذف‌شده باشد. خاموش کردن پرچم، محصولات قبلی را حذف نمی‌کند.
برای حذف محصولات و تصاویر علامت‌گذاری‌شده (برگه‌ها و محصولات واقعی حفظ می‌شوند):

```powershell
docker compose run --rm wpcli bash /scripts/demo-remove.sh
```

برای بازسازی نمونه‌ها در محیط محلی:
```powershell
docker compose run --rm wpcli bash /scripts/demo.sh
```

پس از ادغام Pull Request توسط خودتان، دریافت آخرین تغییرات:
```powershell
git pull
docker compose up -d
docker compose run --rm wpcli bash /scripts/setup.sh
```

اگر نسخهٔ محلی قدیمی دارید و نمونه‌ها را می‌خواهید، بدون ویرایش فایل:
```powershell
docker compose run --rm -e ABRANG_DEMO=1 wpcli bash /scripts/setup.sh
```

**هشدار ویرایشگر سایت:** تغییر قالب در «نمایش ← ویرایشگر» در دیتابیس ذخیره می‌شود و
فایل‌های جدید گیت را می‌پوشاند. برای دریافت طراحی مخزن، در بخش طراحی ← قالب‌ها، منوی
سه‌نقطهٔ قالب تغییرکرده را باز کنید و «پاک کردن سفارشی‌سازی‌ها / بازنشانی» را بزنید.
برای سربرگ و پابرگ نیز در «الگوها ← بخش‌های قالب» همین کار را انجام دهید.
نشان فعلی سربرگ، بلوک «عنوان سایت» با فونت وزیرمتن است؛ برای لوگوی واقعی، در ویرایشگر سربرگ آن را با بلوک «نشان سایت» و تصویر آپلودشده جایگزین کنید.
نوار اعلان یک گروه مستقل در بالای سربرگ است و می‌توان آن را ویرایش یا حذف کرد.

در صفحهٔ Pull Request ← Checks ← CI، بخش Artifacts، فایل `screenshots` را دانلود کنید:
تصویر کامل موبایل، دسکتاپ و منوی باز موبایل برای بازبینی شماست.


### به‌روزرسانی فروشگاه، دسته‌ها و صفحهٔ محصول (قدم ۳)

قالب فروشگاه (`/shop/`), آرشیو دسته‌ها (`/product-category/.../`), صفحهٔ تکی
محصول (گالری راست، خلاصه چپ با انتخاب رنگ برای محصول متغیر), جستجو و صفحهٔ
۴۰۴ فارسی و راست‌چین آماده‌اند. فیلترهای قیمتی/برند/رنگ/موجودی/حراج در سایدبار
دسکتاپ (راست) و پنل تمام‌صفحهٔ موبایل «فیلترها» کار می‌کنند؛ صفحه‌بندی ۱۶ تایی
با ارقام فارسی است.

### دریافت اصلاحات ظاهری و تصاویر نمونهٔ جدید

برای نصب محلی قدیمی، پس از ادغام و `git pull`، این دو دستور فقط محصولات و تصاویر
علامت‌گذاری‌شدهٔ آزمایشی را پاک و با تصاویر مربعی جدید بازسازی می‌کنند؛ محصولات واقعی
و برگه‌ها باقی می‌مانند. **روی سایت واقعی نمونه تولید نکنید.**

```powershell
docker compose run --rm wpcli bash /scripts/demo-remove.sh
docker compose run --rm -e ABRANG_DEMO=1 wpcli bash /scripts/setup.sh
```

اعداد قیمت فارسی و جداکنندهٔ هزارگان «٬» هستند؛ ورودی تعداد و داده‌های عددی
محصولات همچنان عدد عادی می‌مانند.

## چگونه محصولات واقعی را اضافه کنم؟ (قدم ۳) — ورود دسته‌جمعی با اکسل

### قدم ۱ — قالب را پر کنید

فایل‌های قالب داخل `docs/` هستند و هر دو UTF-8 با BOM هستند تا اکسل ویندوز فارسی را درست نشان دهد:

- `docs/products-template.xlsx` — پیشنهادی (دارای ردیف توضیح فارسی زیر سربرگ، کامنت روی هر ستون و اعتبارسنجی `publish/draft` و اعداد)
- `docs/products-template.csv` — همین ستون‌ها به شکل CSV

ستون‌ها (۱۶ ستون، به ترتیب):

`sku` (الزامی، یکتا، انگلیسی مثل `ABR-001`) · `name` (الزامی، فارسی) · `category_slug` (الزامی، یک یا چند با `|` مثل `pens` یا `pens|notebooks`) · `regular_price` (الزامی، تومان فقط عدد — ارقام فارسی و کاما هم قبول است) · `sale_price` (اختیاری، باید کمتر از اصلی باشد) · `stock_qty` · `short_description` · `description` · `brand` · `color` · `size` · `material` · `pack_size` · `weight_grams` · `tags` (با `|` یا `،`) · `status` (`publish` یا `draft`)

سه ردیف نمونه پر شده است — آن‌ها را پاک کنید و محصولات خود (حتی ۱۰۰+ ردیف) را وارد کنید.
برای دیدن `category_slug`‌ها: پیشخوان → محصولات → دسته‌ها → ستون «نامک».

> می‌توانید تک‌محصول را مثل همیشه در پیشخوان → محصولات → افزودن محصول هم بسازید یا ویرایش کنید — ورود اکسلی فقط برای دسته‌جمعی است و جایگزین روش عادی نمی‌شود.

### قدم ۲ — فایل و تصاویر را در `./import` بگذارید

پوشهٔ `./import` روی کامپیوتر شماست (در گیت نمی‌رود، فقط `README.txt` آن در گیت است) و به صورت فقط-خواندنی در کانتینر با نام `/import` سوار می‌شود.

```powershell
# از داخل پوشهٔ پروژه:
Copy-Item docs/products-template.xlsx import/products.xlsx
# حالا import/products.xlsx را در اکسل باز و پر کنید و ذخیره کنید

# تصاویر را آماده کنید — نام هر فایل باید دقیقاً SKU باشد:
#   ABR-001.jpg        → تصویر اصلی
#   ABR-001-2.jpg      → تصویر دوم (گالری)
#   ABR-001-3.jpg      → تصویر سوم
# پسوند jpg/jpeg/png/webp همه قبول است، حروف بزرگ/کوچک فرقی نمی‌کند
# آن‌ها را یا در یک پوشه یا یک فایل zip در import بگذارید:
Copy-Item -Recurse C:\Photos\Abrang\*.jpg import/images/
# یا
Compress-Archive -Path C:\Photos\Abrang\* -DestinationPath import/images.zip
```

### قدم ۳ — بررسی آزمایشی (بدون ذخیره)

```powershell
docker compose run --rm wpcli bash /scripts/import-products.sh /import/products.xlsx --dry-run
```

خروجی:

- اگر ردیفی خطا داشته باشد، گزارش فارسی ردیف‌محور چاپ می‌شود، مثلا:
  `ردیف ۵: ستون category_slug دسته با slug «unknown-cat» یافت نشد.`
  `ردیف ۷: قیمت حراج (60000) باید کمتر از قیمت اصلی (50000) باشد.`
  `ردیف ۴ و ۹: شناسهٔ «ABR-010» تکراری است.`
  و **هیچ محصولی وارد نمی‌شود** (مگر با `--skip-invalid`).

- اگر بی‌خطا بود، لیست «ایجاد / به‌روزرسانی» ردیف‌ها چاپ می‌شود.

### قدم ۴ — ورود واقعی محصولات

```powershell
docker compose run --rm wpcli bash /scripts/import-products.sh /import/products.xlsx
```

نتیجه مثل:

`واردسازی تمام شد — ۱۲۷ محصول ( ۱۲۰ ایجاد، ۷ به‌روزرسانی ).`

SKU معادل شناسه است — اجرای دوباره با همان فایل، محصولات را **به‌روزرسانی** می‌کند، نه تکراری.  
اگر فقط ردیف‌های سالم را می‌خواهید وارد کنید:

```powershell
docker compose run --rm wpcli bash /scripts/import-products.sh /import/products.xlsx --skip-invalid
```

### قدم ۵ — ورود تصاویر

```powershell
docker compose run --rm wpcli bash /scripts/import-images.sh /import/images
# یا برای فایل فشرده:
docker compose run --rm wpcli bash /scripts/import-images.sh /import/images.zip
```

خروجی گزارش می‌دهد: چند تصویر اصلی/گالری وارد شد، چند تکراری نادیده گرفته شد، کدام SKUها بدون تصویر ماندند و کدام فایل‌ها بدون SKU همتا بودند.
